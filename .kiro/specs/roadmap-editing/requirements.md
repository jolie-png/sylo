# Requirements Document

## Introduction

The roadmap-editing feature enhances the Sylo dashboard by allowing students to personalize their roadmap. It introduces inline editing of AI-generated step cards (preserving original reasoning), a notes system for attaching personal context to any roadmap item, and term-based goal scheduling that aligns with academic semesters rather than arbitrary calendar dates.

## Glossary

- **Dashboard**: The main roadmap view rendered at `/dashboard` showing the student's sequenced steps.
- **Sylo_Step**: A roadmap step generated by Sylo's AI engine, stored as `{ id, opportunityId, reasoning, status }` in `roadmap.steps`.
- **Custom_Step**: A user-created roadmap step stored in `customSteps` with `{ id, title, note?, targetDate?, status }`.
- **Step_Card**: The visual card rendered for either a Sylo_Step or Custom_Step in the dashboard list.
- **Original_Reasoning**: The AI-generated `reasoning` string on a Sylo_Step that explains why the step was recommended.
- **User_Note**: A personal annotation a student attaches to any step for reminders, context, or customization.
- **Note_Indicator**: A visual badge or icon on a Step_Card signifying that a User_Note exists.
- **Inline_Edit_Mode**: A UI state on a Sylo_Step card where the user can type a custom note without navigating away.
- **Academic_Term**: A semester-relative label combining a season (Fall, Spring, Summer) and an academic year (First year, Sophomore, Junior, Senior), e.g. "Fall Junior Year".
- **Store**: The Wayfind React context provider that manages state and persists to localStorage.

## Requirements

### Requirement 1: Inline Editing of Sylo Steps

**User Story:** As a student, I want to add my own notes to Sylo-recommended roadmap steps so that I can personalize the AI's suggestions without losing the original reasoning.

#### Acceptance Criteria

1. THE Dashboard SHALL display a pencil edit icon on each Sylo_Step Step_Card.
2. WHEN the user clicks the edit icon on a Sylo_Step, THE Dashboard SHALL enter Inline_Edit_Mode for that step.
3. WHILE in Inline_Edit_Mode, THE Dashboard SHALL display a text input area where the user can type a User_Note.
4. WHILE in Inline_Edit_Mode, THE Dashboard SHALL continue to display the Original_Reasoning in a secondary/dimmed visual treatment.
5. WHEN the user submits or closes Inline_Edit_Mode with content entered, THE Store SHALL persist the User_Note associated with that Sylo_Step's opportunityId.
6. THE Store SHALL preserve the Original_Reasoning unchanged when a User_Note is saved.
7. WHEN a Sylo_Step has a saved User_Note, THE Dashboard SHALL display the User_Note alongside the Original_Reasoning on the Step_Card.
8. WHEN the user opens Inline_Edit_Mode on a Sylo_Step that already has a User_Note, THE Dashboard SHALL pre-populate the text input with the existing User_Note.
9. WHEN the user clears the User_Note text and submits, THE Store SHALL remove the User_Note for that Sylo_Step.

### Requirement 2: Notes System for Roadmap Items

**User Story:** As a student, I want to attach personal notes (dates, reminders, links) to any roadmap step so that I can keep all my planning context in one place.

#### Acceptance Criteria

1. THE Dashboard SHALL support User_Notes on both Sylo_Steps and Custom_Steps.
2. WHEN a step has a User_Note, THE Dashboard SHALL display a Note_Indicator on the Step_Card.
3. WHEN the user clicks the Note_Indicator or a designated note trigger on a Step_Card, THE Dashboard SHALL display the full User_Note content in a popover or small modal.
4. THE Dashboard SHALL keep Step_Cards compact by not displaying full note text inline by default.
5. WHEN the user opens the note view for a Custom_Step, THE Dashboard SHALL show the existing `note` field content as the User_Note.
6. WHEN the user edits a User_Note on a Custom_Step, THE Store SHALL update the `note` field of that Custom_Step.
7. THE Store SHALL persist all User_Notes to localStorage so they survive page refreshes.
8. IF localStorage write fails, THEN THE Store SHALL retain the User_Note in memory for the current session.

### Requirement 3: Term-Based Goal Scheduling

**User Story:** As a student, I want to set goals by academic term (e.g. "Fall Junior Year") instead of specific calendar dates so that my timeline naturally aligns with the school year.

#### Acceptance Criteria

1. THE Dashboard SHALL display an academic term selector instead of a date picker in the Custom_Step creation form.
2. THE Dashboard SHALL display an academic term selector instead of a date picker in the Custom_Step editing form.
3. THE academic term selector SHALL present options combining a season (Fall, Spring, Summer) with an academic year from the YEARS constant (First year, Sophomore, Junior, Senior).
4. THE academic term selector SHALL order terms chronologically relative to the student's current profile year.
5. WHEN the user selects an Academic_Term for a Custom_Step, THE Store SHALL persist the term value in place of the calendar date.
6. WHEN a Custom_Step has an Academic_Term set, THE Dashboard SHALL display the term label (e.g. "Fall Junior Year") on the Step_Card.
7. THE Store SHALL migrate the `targetDate` field on Custom_Step to support Academic_Term string values.
8. IF an existing Custom_Step has a calendar date stored in `targetDate`, THEN THE Dashboard SHALL still render that date correctly for backward compatibility.
